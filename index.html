About Me

TQbot: Bio-inspired Quadruped

Robotics ROS2 Python Raspberry Pi

Dissertation project developing the motor control software for TQbot, a quadruped robot with a bio-inspired tensegrity spine providing all three spinal degrees of freedom, and fifteen system-wide degrees of freedom.

Implements a three-layer ROS2 multi-motor control architecture that commands sixteen Unitree A1 motors across six RS485 buses. The system is commanded from a Python control shell, and safeguarded through a safety layer.

What was implemented

  • A three-layer ROS2 multi-motor control architecture consisting of per-motor state, per-bus communication, and ROS2 messaging.
  • Validation of multi-motor control architecture by moving multiple motors across multiple buses simultaneously.
  • Numerical reimplementation of prior kinematics solutions, validated by round trip testing in software.
  • A safety infrastructure including emergency stops, motor limits, and motor state validation.
  • A Python control shell reducing ROS2’s operational complexity into user-friendly prompts.
  • Deployment of hybrid PD control on TQbot, allowing for position holding within a measured error margin.
  • A mock-hardware test suite, allowing the motor stack and kinematics to be validated without the robot

Results

TQbot’s spine was damaged in transit after the University of York’s School of PET Demo-Day, thus all sixteen motors were never fully commanded simultaneously.
Before the damage, the four spine motors held the spine in a tensioned flat configuration while the front-left leg moved to various targets, validating concurrent multi-bus control. After the damage, position control of the twelve leg motors was demonstrated to my supervisor whilst the spine was held in place, producing a gantry-assisted standing posture in which each leg held its position under external force.
All 22 motor stack tests and 88 kinematics tests passed, with round-trip residuals below 1.3 × 10⁻¹⁶m.
My work successfully bridged the software gap left in the pre-existing PhD work, and provides a solid foundation for future free-standing and locomotion work.

Autonomous Maze Solving Robot

Robotics Embedded C++ Arduino

A fully autonomous differential-drive robot with a custom-built chassis, using the Arduino Nano 33 BLE to navigate unknown maze environments.

Houses 4 infrared sensors, 2 ultrasonic sensors, 2 motors, and a custom-built battery pack holder.

What was implemented

  • 2 custom laser-cut plates capable of housing sensors, motors, the battery, and the microcontroller
  • Multi-sensor fusion, using 4 IR sensors (90° and 45°) and 2 ultrasonic sensors (front and back) for obstacle detection
  • Wheel odometry using encoder interrupts to calculate distance travelled and displacement
  • Gyroscope bias calibration and closed-loop angle control for precise turns
  • Trigonometric wall-angle estimation using 45°/90° sensor comparison to maintain parallel wall alignment
  • Utilisation of bluetooth to stream data wirelessly for ease of debugging
  • Finite state machine controlling behaviours: drive, wall avoidance, repositioning, and turning

Results

The robot successfully navigated both known and unseen maze environments, demonstrating reliable autonomous obstacle avoidance, stable wall-following behaviour, and accurate gyroscope-corrected turning.
Key strengths included consistent wall alignment, obstacle avoidance, and recalibration of the gyroscope before major turns to ensure angular accuracy.

FollowerFeuds

Simulation Python

A BeyBlade-style game implementing a real-time 2D physics simulation built in Python, attracting 400+ daily users on TikTok.

Implements rigid-body motion, collision detection, and momentum transfer. Using a modular state-driven architecture, capable of handling continuous real-time updates.

What was implemented

  • A rigid-body 2D physics engine with velocity, mass, and collisions with overlap prevention
  • Momentum exchange using tangent/normal vector decomposition to conserve momentum while preserving tangential velocity
  • A hierarchical state-based logic architecture managing simulation phases
  • 4 roles which each player has a chance of selecting:
    None: Default role (70%)
    Venom: Deal a tick damage after every hit (10%)
    Clone: Once falling beneath 50 health, spawn in a clone of yourself with both instances getting 30 health (10%)
    Glitch: 3 opportunities to dodge dagger attacks (10%)
  • 3 randomly spawning items that players are able to interact with:
    Health Pack: Boosts a players health by 5 points (caps at 100)
    Shield: Temporarily blocks a player from taking damage from opponents, can be broken early if hit by a dagger
    Dagger: Boosts collision damage from 1-3 points to 15-25 points
  • Modular design enabling easy addition of new mechanics, arenas, and gameplay modifiers

Results

The final system delivered stable multi-body dynamics with consistent physics. The engine maintained stability during high-speed impacts and multi-object collisions, demonstrating reliable momentum conservation.
Posting daily videos of gameplay on TikTok, the project reached 500+ daily users as of March 2026. Validating both the performance of the project and user engagement.

Flocking Simulator

Simulation Java

Real-time flocking simulation in Java, applying object-oriented programming principles to simulate emergent flocking behaviour in autonomous boids.

Each boid follows rules for cohesion, alignment, and separation, whilst maintaining avoidance of static obstacles on a 2D canvas.

What was implemented

  • Implementation of core flocking rules: separation, alignment, and cohesion to produce emergent behaviour
  • Neighbour detection using distance-based filtering and spatial partitioning to significantly reduce computational complexity
  • Functional obstacle avoidance based on geometric calculations and collision prevention logic
  • Efficient object-oriented architecture using inheritance, composition, and interfaces
  • Customisable simulation controls through a GUI, allowing users to adjust boid behaviour dynamically

Results

The final result includes a fully working interactive flocking simulation with a clear GUI, working controls, and visual accuracy.
Key strengths of my project included a responsive reset/disable feature, dynamic visual feedback where boids became greener as flocking strength increased, clean and reliable execution, and a well-structured object-oriented design.

Parameterisable Processor

Simulation VHDL

A parameterisable processor datapath in VHDL, built to be reusable, and simulated within Vivado 2023.2.

Modular components including an ALU, register bank, and control logic are used to execute a custom single-cycle multiplication routine.

What was implemented

  • A parameterisable ALU supporting signed arithmetic, bitwise logic, and shift/rotate operations
  • Comprehensive flag generation including overflow detection
  • A dual-read, single-write register bank built using for-generate constructs and synchronous reset D flip-flops
  • Custom multiplexer-based selection logic
  • A complete datapath architecture and FSM-based control unit capable of executing an 8-bit multiplication algorithm using 16-bit operations
  • Self-checking testbenches using assert/report mechanisms
  • RTL schematics and synthesis reports confirming hardware structure and implementation

Results

The final system demonstrated correct multiplication functionality across multiple test cases, with simulation waveforms clearly showing accurate data propagation, state transitions, and control signal generation.
Key strengths of this project included a strongly modular design, robust test methodology, and clear documentation.
